## 实际验证

本轮环境为 Node.js 22.23.2，Harness 0.2.1-rc.3。所有验证使用临时目录，未启动真实交易，也未创建用户的长期模拟账户。

| 验证 | 结果与证据范围 |
| --- | --- |
| `npm run check` | 类型检查、18 项测试、宿主/客户端/worker 构建与构建产物 smoke 检查通过 |
| 领域与引擎测试 | 逐笔金额可手算；费用、成本、止损跳空、同根歧义、无交易空值、确定性重放通过 |
| 时序测试 | 修改未来价格/成交量不改变此前成交；同一时间多个交易对的开盘执行不读取其他交易对稍后的收盘价 |
| 权限测试 | 真实 Harness Tools 注册与 scope 隔离；真实 Connection exact-route 拒绝非 owner；身份伪造与未知工具被拒绝 |
| 模拟事件测试 | 注入行情事件执行、重复事件去重、缺口暂停；并发重复启动只创建一个运行实例，两账户争抢只允许一个成功 |
| 恢复与取消测试 | 重启暂停、提交身份重试、修订冲突、下载取消后不被迟到异常改写、备份 hash/引用/账本校验通过 |
| 客户端异步测试 | 网络失败沿用提交身份重试；保存期间继续编辑不会丢失新输入 |
| 构建后 worker | 通过打包后的服务提交合成数据回测，真实 worker 完成并产生 14 笔模拟成交 |
| `npm run check:launch` | 临时启动完整 Harness；未登录请求 401，跨来源请求 403；登录后创建数据/草稿/发布/回测成功，14 笔成交；真实 HTML 启动清单含本插件 |
| `npm run check:market` | 公共服务器时间、BTCUSDT TRADING 元数据与三根历史 K 线的只读连通性检查通过 |
| 十万根基准 | 100,000 根合成 1m K 线，约 9,113 ms；进程 RSS 约 524 MiB；982 笔模拟成交；仅代表本机这次基准 |

基准命令为 `node --import tsx scripts/benchmark.mjs`。RSS 包含数据生成、回测与结果，不等于独立 worker 的堆内存。单次任务上限与资源预算分开：最多一百万根，worker 堆上限 768 MiB，时限五分钟；超过预算明确失败，不保证任意规模在任意机器上完成。

模型质量与 UI 验证边界：已验证公开客户端模块加载、slot 注册、服务端 React 渲染和组件事件/异步逻辑；未执行真实浏览器的排版与多尺寸视觉测试。未使用用户凭据进行真实模型质量评测。模拟事件逻辑通过受控行情测试，公共 REST 已实测；尚未做跨日真实行情模拟盘稳定性运行。

## 与最初方案的具体实现选择

- Web 首版使用参考项目的 `/api/quant/*` exact Fetch routes，通过宿主 Connection 的信任、登录与 owner 验证，再解析标准 RPC envelope。完整启动验证发现该锁定版本独立 `rpc.handle` 路径存在服务上下文依赖问题，因此采用已实测的公开 exact-route 机制。
- 历史任务中断后按原 manifest 重新计算，保持幂等与可复现；当前未实现部分计算进度的断点续算。
- 模拟账户以 JSON checkpoint 保存运行投影，同时把成交、账本、决策放入独立关系表，并同事务核对，防止只靠覆盖账户 JSON 掩盖事实。
- 首版订单是意图、拒绝或整单即时虚拟成交，没有部分成交或长期挂单。成交资金结算为原子操作，不展示虚构的长期冻结余额。
- 公开成交报价驱动模拟盘执行；保护退出每十秒采样，和历史 K 线的根内保守约定有差异。断线缺口暂停后手动恢复，不将补历史数据伪装成当时实际观察。
- 样本外区间由用户按时间手动划定并单独运行；保留所有实验与参数，但尚未实现独立的样本外锁定/揭示工作流。
- 完整备份 64 MB 上限；超出后使用停机目录备份。恢复不重建 Harness 对话。
- Desktop 安装与长时间模拟运行尚未验证；真实下单、合约、杠杆和链上交易不属于本次首版范围。

## 运行与复查

```sh
npm start
npm run check
npm run check:launch
npm run check:market
npm run pack
```

`check:launch` 只绑定临时回环端口并自动结束服务；`check:market` 只读访问公共行情。一般使用不需要这两项额外检查。

新会话选择「量化研究助手」，打开「量化工作台」。可先按[使用说明](使用说明.md)完成合成数据的离线研究闭环，再准备自己的历史数据和模拟配置。模型与登录沿用宿主设置。
