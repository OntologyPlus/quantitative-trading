# 稳健性研究实施记录

日期：2026-10-31。范围：整体改进方案第二阶段。

## 本轮实现

新增版本化、可选的稳健性协议。启动前冻结成本倍率、参数扰动、扩展训练窗口数量和诊断通过率。默认两个候选共需20项实验，计入原项目实验与计算预算，不改写既有委托或报告。

| 能力 | 实现与边界 |
| --- | --- |
| 成本敏感性 | 所选候选在验证期按冻结倍率逐项真实重放，使用同成本口径基准；显示实际情景，不插值推断未测盈亏平衡费率 |
| 参数稳定性 | 慢均线/突破入场回看期上下扰动，生成独立不可变研究版本；取整、合法边界裁剪与去重，不能发布或直接用于模拟 |
| 滚动验证 | 只使用初始冻结候选池，每窗先按训练结果选策略，再检验下一段；排除后来追加的候选，测试窗口在最终区间之前且不重叠 |
| 收益归因 | 最终区间按UTC月末权益差、交易对成交现金流与期末持仓市值归因，另示盈利平仓交易集中度；保留最后一根收盘估值 |
| 证据与门槛 | 新实验复用run/manifest/result身份；归因字段可逐项核对；诊断按冻结通过率纳入通过/拒绝/证据不足结论 |
| 界面与导出 | 委托可选择并核对协议，报告显示成本曲线和对照表、训练依据、归因表，Markdown与JSON保留结果及限制 |
| 恢复和批准 | 恢复前重新检查窗口、成本、训练引用、不可变策略、派生结果及结论；伪造已重新计算hash的报告也不能绕过判定 |

- 后续协议版本与原始参数展示调整：26项相关研究/归因/组件测试、类型检查与构建通过。
- 新增针对窗口时间隔离、后续结果不影响较早窗口选策、初始候选池隔离、费用和期末浮盈亏手算、预算/取消、备份篡改与研究门槛的回归。
- `npm run check:browser`：真实认证宿主、原六项基础研究和新增20项worker研究通过；桌面/手机成本曲线、参数/滚动结果、归因字段证据跳转和断线恢复通过。已人工查看 `.runtime/browser-check/robust-desktop.png` 与 `robust-mobile.png`。数据为合成样本，只证明流程与界面，不代表市场有效性。
- GitNexus已更新。原始 `detect_changes(scope=all, limit=1000)` 对已跟踪改动报告9个文件、50个符号、40条受影响流程，`partial=false`、`truncated=false`，风险critical；新增归因、诊断计划、完成判定、恢复校验和结论函数另作调用图核对，风险critical，结果组件风险low。以上风险没有被视为通过测试即可忽略；关键路径已做上述故障、证据、批准与恢复验证，动态调用解析仍有图工具自身的边界。原始结果保存在 `.runtime/robustness-graph-review.json`。

## 使用与限制

新建研究时勾选“启用稳健性研究”，随后核对协议再启动。流程没有启用模型时也能完整执行。旧委托仍走原基础路径，不能自动扩展已授权预算。

通过率门槛不等于统计显著性，滚动窗口不拼接为组合净值，成本/参数敏感性不属于新盲测。本轮没有增加新策略模板、真实订单或后台自动改参。第三阶段的模拟偏差复盘与运行变更比较尚未实施。

真实模型质量评测、七日公共行情观察、目标用户试用与Desktop安装验证仍独立保留，不能以本轮自动测试代替。
