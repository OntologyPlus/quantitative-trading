# 常驻运行与质量验证

版本：0.2.0；更新日期：2026-10-30。

## 本地服务

```sh
npm run setup
npm run start:server
```

启动带认证的 Harness Web 宿主并保持研究与模拟循环运行，不自动打开浏览器。终端打印的登录链接属于本机认证入口。关闭浏览器不会停止服务；退出进程、电脑休眠或断电会中断观察。默认仅绑定 `127.0.0.1`。

项目数据保存在 `.quant-data/`，安装包模式保存在 `$DSH_HOME/plugins-data/quant-assistant/`。一个目录仅允许一个有效执行者。首次打开旧库时，取得执行租约后建立 `quant.sqlite.schema1.bak` 并迁移到 schema 2。完整目录备份须包含 `datasets/`、`results/` 与数据库，不能只复制主 SQLite 文件。

需要系统开机自启时，可让操作系统服务管理器以项目目录为工作目录、调用实际安装的 Node 和启动脚本，并保留相同 `DSH_HOME`。本项目没有自动写入系统登录项。独立服务器与 Desktop 的部署、升级和权限需分别验证；本轮未交付云端可用性保证。

研究重启行为由委托授权决定。模拟盘重启后始终暂停，手动恢复时补充的数据只重建指标，不回填缺口期间成交。

## 自动与浏览器检查

```sh
npm run check
npm run check:launch
npm run check:market
npm run check:browser
npm run benchmark:projects
```

`check:launch` 在临时目录启动完整宿主，验证匿名与跨来源拒绝、登录和认证 RPC。`check:browser` 还启动独立的临时无界面 Chrome，真实渲染客户端，通过认证 RPC 完成研究，并验证宽窄布局、证据跳转和断线恢复。截图保存在 `.runtime/browser-check/`。检查会自动结束自己启动的进程。

非 macOS 或 Chrome 未安装在默认位置时，通过 `QUANT_CHROME_PATH` 指定已安装的 Chrome/Chromium 可执行文件。浏览器视觉与交互未执行时，应明确保留未验证状态。

## 真实模型评测

项目包含 20 个固定案例，覆盖正常研究、成本、证据、样本不足、预算、最终区间和能力外请求。每次试验使用独立临时会话与数据目录，保留模型路由、项目、实验、报告、用量和自动判定记录。

先按 Harness 模型配置提供有效凭据，从该配置取得实际 provider/model 名称：

```sh
npm run check:eval -- --provider YOUR_PROVIDER --model YOUR_MODEL --limit 1 --repeat 1
```

完整计划为：

```sh
npm run check:eval -- --provider YOUR_PROVIDER --model YOUR_MODEL --limit 20 --repeat 3
```

凭据通过提供方支持的环境配置传入，不把密钥写到命令行或结果文件。脚本会真实调用所选模型并准备公共行情；可先用一个案例确认成本和可用性。结果写入 `.runtime/evaluations/`。

自动判定检查状态、预算、能力外任务是否在实验前停止，以及报告证据是否可核对。解释质量、是否回应真实研究问题、是否遗漏反证等需要人工评分，`qualityGraded` 默认保持 `false`。受控适配器通过只代表宿主与调度集成通过。

## 公共行情持续观察

```sh
npm run check:soak -- --seconds 60
```

使用临时模拟账户和公共行情，不访问真实订单接口。先等待公共流就绪，再记录状态、有效行情时间和故障，结束后停止账户和临时宿主。结果写入 `.runtime/soak/`。

七日观察使用：

```sh
npm run check:soak -- --seconds 604800
```

这需要机器和网络真实保持运行七天。暂停、断线、报价错误、重新连接与未观察区间必须保留在记录中；不能用短时通过推导长期稳定性。
