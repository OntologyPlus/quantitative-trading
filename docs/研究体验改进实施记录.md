# 研究体验改进实施记录

日期：2026-10-31。范围：整体改进方案的第一阶段，沿用当前 0.2.0 数据结构。

## 本轮实现

- 委托起点：两个可编辑目标示例、打开已选报告的入口，以及日期、预算和缓存数据覆盖预检查。
- 研究条件：统一根据冻结协议与绑定快照展示范围、时间、资金、费用、滑点、来源与成交约定；UI 与新增 Markdown 报告共用生成逻辑。
- 报告阅读：将所选候选的三阶段依据/反证、必须保留的限制、程序生成的下一步置于前部，支持阶段卡到具体实验及证据核对。
- 进度解释：将阶段和事件说明为正在进行的研究动作，原始事件仍可展开。
- 故障恢复：区分补充问题、模型配置、数据连接、预算授权与未知执行结果，避免重复点击无法推进的恢复操作。
- 后续研究：保留此前未在页面展示的风险、成交量参与率、压力倍数和高级预算值，明确默认模板会重新比较。
- 兼容性：不修改评估判定、预算执行与模拟批准规则；历史报告不重算、不覆盖 hash，存储/备份格式不变。

## 验证

- `npm run check`：类型检查、40 项测试、构建与真实 worker smoke 通过；含六项回测、48 项证据校验。
- 新增回归覆盖实际费用/来源、数据预检查、反证建议、恢复入口、隐藏配置继承、报告导出恢复与历史正文身份。
- `npm run check:browser`：真实 Chrome 桌面/手机布局、认证 RPC、六项 worker 回测、目标示例、实际费率、报告阶段卡证据跳转及断线恢复通过。截图人工检查后收起已完成研究的过程详情，切换报告自动定位阅读区；调整后再次通过浏览器回归。
- 最后一次界面调整后，类型检查、8 项相关组件/体验测试及构建通过。
- GitNexus 索引已更新至当前代码。完整 `detect_changes(scope=all, limit=500)` 原始结果为 7 个已跟踪文件、18 个符号、12 条受影响流程，`partial=false`、`truncated=false`；风险为 high，涉及研究交付与客户端入口。新增模块另作调用图影响核对：条件、评估说明与下一步生成函数被标为 critical（同时影响报告和客户端），费用格式函数为 high；已覆盖报告交付、恢复、批准及浏览器回归。原始变更结果保存在 `.runtime/graph-change-review.json`。这不代表图索引能解析全部动态调用。

## 后续阶段

本轮没有实现分段收益归因、多个成本情景、参数邻域稳定性或滚动验证，也没有改变模拟执行模型。上述能力属于第二、三阶段，需要新增协议、计算及证据契约，不能用阅读层的解释替代。

真实模型 20×3 研究质量评测、七日公共行情观察、目标用户独立试用与 Desktop 安装验证仍未完成。本轮自动检查不能视为这些门槛通过。
