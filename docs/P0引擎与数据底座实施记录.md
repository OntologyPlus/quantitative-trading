# P0 引擎与数据底座实施记录

引擎版本升至 `quant-engine-0.2.0`。旧版本的回测结果 hash 和证据仍可校验；新提交的实验使用新引擎。

## 变更

| 项 | 内容 |
| --- | --- |
| 精确引擎提速 | 均线/突破信号改用 10^16 定点 BigInt 精确计算并滚动求和（`src/engine/fixed.ts`）；空仓且资金不变时复用权益标记；收盘标记的回撤文本延迟到确实保留时计算；阈值判断改为精确乘法比较。成交、账本、权益曲线与指标逐字节不变。 |
| 决策日志瘦身 | 回测不再逐根写入 `WARMUP` / `NO_SIGNAL`，改为 `state.idle` 计数；序号仍然推进，订单、成交、决策身份不变。模拟盘照旧逐根记录。 |
| 参数扫描 | `src/engine/sweep.ts` 为 Float64 列式筛选内核，与精确引擎规则一一对应；`src/host/sweep-pool.ts` 用 worker 线程和 SharedArrayBuffer 并行；研究实验室新增 `parameter-sweep`，对排名靠前的候选自动用精确引擎复核，只有复核数字可引用。 |
| 批量下载 | 完整历史月份改为下载 data.binance.vision 月度归档并校验 SHA-256，缺档月份和当月走 REST；兼容 2025 年起的微秒时间戳。 |
| 缺口容忍 | 新快照允许缺口：缺失不超过 1%，单个缺口不超过 72 小时；缺口数量写入 `quality.gaps`，备份恢复会复核。信号对应的开盘落在缺口里时作废，记 `DATA_GAP`。重复、乱序、未收盘照旧拒绝；模拟盘预热数据仍要求连续。 |

## 验证

- `tests/engine-golden.test.ts`：8 组策略/风控/多标的/条件组合，以旧引擎生成的摘要为基准，新引擎全部一致。
- `tests/sweep.test.ts`：筛选内核与精确引擎在交易数、收益、回撤、暴露、Sharpe 上误差 < 1e-6；线程池与单线程结果一致。
- `tests/data-archive.test.ts`：缺口策略、两个引擎的缺口作废行为、zip 解析、校验失败、归档缺失回退 REST。
- 原有可在无 Harness 依赖环境运行的测试全部通过（engine、data、attribution、monitor、paper、projects、review-fixes、enhancements、service、dispatch-diagnosis）。

| 筛选内核单组参数 | — | 约 5.8 ms |

## 未完成

- 单次精确回测仍未到 100 ms：每根 K 线都要产出精确的权益曲线字符串，这部分仍由 Decimal 计算。把曲线改为按需或降采样会改变回撤等指标，需要单独决策。
- 行情仍以 JSON 快照存储，尚未换成列式文件；百万根数据的内存占用仍偏高。
- 扫描结果尚未接入研究委托的自动流程和多重检验校正（计划在 P2）。
